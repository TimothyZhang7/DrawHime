# 运维执行规范

## 标准快速链路

1. 确认仓库、适用 `AGENTS.md` 和工作树，只通过 `rg --files` 定位真实文件。
2. 读完入口、调用方、共享契约和最终写入方后修改，执行 `git diff --check`。
3. 开发阶段只运行受影响目标的最小检查，共享契约变化才扩大范围。
4. 检查活动任务与目标健康状态，优先运行 `node scripts/quick-deploy.mjs --changed --dry-run` 推导最小端点。
5. 执行一次 `node scripts/quick-deploy.mjs --changed`；需要人工覆盖时才显式传入 `--target <target>`。
6. 验证目标 `/health`、必要的 `/ready` 或 `/health/db`、公网入口和本次业务状态。
7. 全部验收成功后，用明确路径暂存、检查暂存区并创建部署提交。
8. 同步公开源码时仅复制已部署文件，比较内容后提交、推送并验证远端 SHA。

## 命令约束

- 固定文本使用 `rg -F`；复杂搜索拆开执行，禁止临时拼接未验证正则。
- PowerShell 到 SSH 的复杂逻辑通过标准输入发送多行脚本，不压缩成多层插值单行命令。
- 独立并行诊断需要保留全部结果时使用 `Promise.allSettled`，单条无匹配不得隐藏其他输出。
- 网络与 Runtime 轮询使用有上限的重试、退避和总截止时间，单次超时不作为最终故障结论。
- 生产查询显式投影必要字段，不输出提示词、参考图、完整队列载荷、令牌或私有环境变量。
- `apply_patch` 前用 `rg -n -F` 核对精确上下文，失败后重新读取目标行并使用最小补丁。
- 任一命令失败都必须修正并重新通过当前步骤，部署或验收失败时不得创建已部署提交。
- `--changed` 只读取 Git 已跟踪改动；新文件先用 `git add -N` 登记。只改部署工具或文档时使用 `source`，不构建、不发布静态站点、不重启 PM2。

## 错误复盘

| 错误 | 预防措施 |
|---|---|
| 读取不存在的文档 | 先执行 `rg --files` 或 `Test-Path` |
| `rg` 正则未闭合 | 固定文本使用 `rg -F`，多个条件拆开 |
| SSH 中 URL 被本地变量或引号破坏 | 使用多行远端脚本并在远端展开变量 |
| 压缩 JavaScript 出现语法错误 | 保持多行、缩进和明确的 `try/finally` |
| GPU 轮询因一次连接超时退出 | 捕获异常、退避重试并交叉验证 readiness、端口和进程 |
| 本地全仓检查与部署门禁重复 | 迭代只跑最小检查，完整门禁只运行一次 |
| 队列诊断输出用户提示词 | 只查询 ID、状态、模型、尺寸、采样参数和耗时 |
| 并行诊断被单条失败整体中断 | 使用可收集全部结果的聚合方式 |
| 补丁上下文不精确 | 先定位原文，再使用最小上下文补丁 |
| 公开目录文件比较出现预期路径差异 | 对源码精确比较；README 等路径适配文件只核验本次片段和登记的允许差异 |
| GitHub 推送出现瞬时 443 超时 | 保留本地提交，最多三次递增退避重试，成功后核对远端 SHA |

部署命令、端点和回滚细节见 [`deployment.md`](deployment.md)。
