# 项目代理约束

- 永远使用中文沟通。
- 所有新增或修改的源码必须有中文注释；新增源码文件必须有中文文件级职责注释。
- 不允许使用假数据、伪接口或跳过鉴权、计费、幂等、错误处理来制造成功结果。
- 本项目数据库、Redis、对象存储与主站物理隔离，不直接连接或查询主站数据库。
- 主站账号通过 SSO 使用，禁止复制密码哈希；主站余额只通过版本化 Integration API 预留、提交和释放。
- GPU Runtime 不得直接暴露公网；所有任务必须经过 scheduler 和 GPU Agent。
- 跨程序请求、响应和事件先登记到 `docs/interfaces/README.md`，再落到 `packages/contracts`。
- 成功响应使用 `{ ok: true, data }`，失败响应使用 `{ ok: false, code, message }`。
- 数据库迁移使用可审计 SQL，禁止以 `db push` 代替生产迁移。
- 未配置真实依赖时 readiness 返回明确未就绪，不使用占位数据模拟可用。
- 读取文件前先使用 `rg --files` 或 `Test-Path` 确认路径；固定文本搜索使用 `rg -F`，禁止未经验证的复杂正则。
- PowerShell 到 SSH 的复杂命令必须通过标准输入传递多行脚本，禁止嵌套三层引号和压缩的远端 JavaScript 单行脚本。
- GPU、ComfyUI 和服务轮询必须容忍瞬时网络超时，使用有上限的重试、退避和总截止时间。
- 生产诊断只输出必要字段，禁止打印用户提示词、参考图、完整 ComfyUI 队列载荷、令牌或私有环境变量。
- 任一命令失败必须修正并重新通过当前步骤；部署或验证存在未解释失败时禁止提交。
- 开发阶段只运行受影响目标的最小检查；完整部署脚本已包含的全仓检查不得提前重复执行。
- 同一任务只允许一次并行初始发现；已读取且未变化的规范、长文档和源码不得重复全文读取，大文件必须先定位再读取相关行段。
- 单页面、单接口和单配置任务直接修改，不追加无关调研、全仓巡检或旁支修复；一个 diff 对同一目标只保留一次成功验证结果。
- 生产验收默认限于目标健康、公网入口和一个代表性业务断言；鉴权或迁移任务各追加一个对应断言，不重复进行同义测试。
- 日常修复默认只更新开发测试环境：桌面源码构建一次生产协议无安装包 EXE，精确覆盖 `E:\DrawHimeStorageTest\drawhime-desktop.exe` 并完成目标专项验收；纯文档任务只执行内容检查与 `git diff --check`。
- 没有当前任务的明确授权时，禁止 `git add`、`git commit`、`git push`、公开仓库同步、GitHub Actions 调度、GitHub Release、生产部署和稳定更新通道变更；历史任务中的授权不自动延续。
- 小型单端任务目标 15 分钟、跨平台任务目标 30 分钟；超时立即停止扩大范围并完成必要链路，但不得跳过鉴权、计费、数据安全、迁移或失败门禁。
- 默认执行顺序为：发现与读链路 → 最小修改 → 受影响目标最小验证 → 更新开发测试环境 → 目标专项验收 → 结束并报告。提交、公开同步、生产部署和正式发布只在当前任务明确授权后追加执行；只有基础设施或明确跨全平台生产变更才使用 `all`。
- 完整命令、失败分支和历史错误复盘见 `docs/operations.md`。
