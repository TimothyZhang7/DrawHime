# 桌面样式目录规范

## 入口

- `../styles.css` 是主工作区唯一入口，只允许按顺序导入模块，不得继续写页面规则。
- `../account.css` 负责账号页，文件较小且职责单一，继续由 `main.tsx` 独立导入。
- `../repository.css` 是仓库入口，只允许导入 `repository/` 下的模块。
- `main.tsx` 必须保留样式入口导入，禁止在页面组件中按运行状态动态加载 CSS。

## 目录职责

- `core/base.css`：主题变量、基础元素、桌面外壳和跨页面通用结构。
- `core/startup.css`、`core/runtime.css`：启动与本地核心环境。
- `core/generation*.css`：本地生成、参数帮助、LoRA 选择和预览交互。
- `core/training*.css`：训练集打标、AI 清洗和 LoRA 训练流程。
- `core/gallery.css`：图库、作品详情和任务记录。
- `core/resources.css`：依赖清单、下载队列和资源进度。
- `core/settings.css`：设置、存储清理和软件更新。
- `core/responsive*.css`：只放跨多个页面的最终窗口约束，不承载页面主样式。
- `components/`：分页等跨页面复用的小型控件样式，不承载具体业务页面布局。
- `repository/`：按列表、详情、训练来源、弹窗、媒体、布局和卡片密度拆分。

## 修改规则

1. 新规则优先写入所属页面文件，不在响应式文件中重复定义完整组件。
2. 跨页面复用的变量和最小基础控件写入 `core/base.css`，业务状态颜色仍由页面文件负责。
3. 同一选择器不得为了覆盖顺序散落到三个以上文件；出现第三处时先合并真实职责。
4. 单文件建议不超过 600 行，超过时按页面子功能继续拆分。
5. 新增样式文件必须包含中文文件级职责注释，并在入口中显式登记导入顺序。
6. 修改全局入口、导入顺序或响应式规则后，必须执行桌面前端构建和真实 WebView 页面验收。
